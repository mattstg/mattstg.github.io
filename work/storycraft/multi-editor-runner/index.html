Multi-editor runner

Agents are slow per task but cheap to run in parallel. Unity, though, wants one project open in one editor. I built a runner that gives one developer three Unity editors at once, each with its own agent, environment and backend, plus the queue and resource manager that keep them all working.

Role
Designed and built it
When
2025 – 2026
Stack
Unity, C#, Claude Code, MCP, git worktrees, a command-line client with a warm daemon
Result
3 Unity editors per developer, each with its own agent; agent commands in about 0.3 s

The parts

  1. Isolated editors. Each agent gets its own git worktree and its own Unity editor. A worktree alone isn't enough: out of the box, neither Unity's command line nor Claude Code could tell the editors apart, so I built a way to identify each editor and keep commands, preferences and agents from crossing over.
  2. Its own environment and backend. Each editor can run its own local backend, so an agent can test backend changes without touching the others, or editors can share one to save RAM.
  3. A task queue. Tasks, whether tickets from Jira or Notion or failures from a test run, are handed out across the three editors.
  4. A resource manager. CPU and RAM are managed across the three editors, so the machine stays usable.
  5. A command-line bridge into the editor. About 48 commands that let agents see the game and play it: snapshots of the UI, taps and typing, screen captures, and signals that say when the game is ready for the next step, so agents don't act on half-loaded screens. A daemon stays warm between calls, so each command takes about 0.3 seconds. Team maintained and extended; I was its main contributor.

Impact

  • One developer could run three tasks that need an editor in parallel, instead of one.
  • Agents check their own work by playing the game, instead of stopping at "it compiles".
  • The same bridge commands run on iPhone dev builds, so tests written once run in the editor and on devices.
  • It's what the overnight test runner runs on.
